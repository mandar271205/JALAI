### Exact precipitation product and physical conversion

Source: NOAA's public GFS AWS archive, `gfs.YYYYMMDD/HH/atmos/gfs.tHHz.pgrb2.0p25.fFFF`. Retrieval uses the `.idx` inventory and bounded HTTP byte ranges, requires HTTP 206 and the exact range, validates the complete GRIB message length/header/trailer, and caches immutable precipitation messages with SHA-256. It never falls back to a full global file or a different variable.

Default product is **interval-mean PRATE**, selected independently from actual GRIB metadata: `shortName=prate`, `typeOfLevel=surface`, `level=0`, `stepType=avg`, `stepUnits=h`, exact reference cycle and start/end steps. For lead `f`, require `startStep=6*floor((f-1)/6)`, `endStep=f`. Instantaneous PRATE and first-variable selection are rejected. Missing/ambiguous matches fail. Stored source fields also include units, valid time, grid type, parameter ID, product definition template and source URI/hash.

PRATE's `kg m**-2 s**-1` is converted to interval amount as `PRATE * 3600 * interval_hours` mm. Successive cumulative interval amounts are differenced **only within the same cycle and origin**, then divided by the reconstructed one-hour duration to obtain mm/h. An origin reset is accepted only at the previous interval's end. APCP (`tp`, surface 0, accum, kg/m² or mm) conversion is also unit-tested; the default is PRATE because early APCP inventory entries can be ambiguous. Unsupported units, gaps, zero duration, mixed products/cycles, negatives and non-finite values fail. Only cancellation negatives smaller than 0.00001 mm may be clipped, explicitly QC-flagged; larger negatives fail rather than concealing a reset.

An actual retrieved f001 field decoded as parameter 3059, template 8, `prate/avg/surface/0`, interval 0–1 h, reference `2023-08-23T18:00:00Z`, valid `2023-08-23T19:00:00Z`, units `kg m**-2 s**-1`. Its message SHA-256 is `a7af17d8e02e975770afb44be98066ccddf54dfb83b89912d13154f97ace7b43`.

### Cadence and spatial alignment

Native near-term cadence is **60 minutes**, with 00/06/12/18 UTC cycles. Output cadence is **30 minutes** at +30/+60/+90/+120. Each output is the mean rate over the preceding half-hour, generated by overlap integration of constant-rate native hourly intervals. An A-mm hour contributes A/2 mm to each half-hour. The method is `uniform_within_native_interval`; these are disaggregated forecasts, not native half-hour information. Cumulative precipitation is never linearly interpolated.

Actual GRIB coordinate arrays define source cell centers and half-cell edges. Longitudes are wrapped and sorted; latitude is made north-up. Regular 0.25-degree spacing is verified, then cropping includes a two-cell interpolation halo. Bilinear resampling uses the existing Mumbai pilot's exact affine, extent, **256×256** dimensions and **EPSG:32643** CRS. API metadata remains **EPSG:4326**, rainfall **mm/h**. Resampling creates no new spatial detail: source resolution remains 0.25 degrees (approximately 28 km). Temporal allocation conserves rainfall amounts; bilinear spatial resampling is not claimed to be an area-conservative remapper.

### As-of policy and leakage protection

`select_gfs_forecast_as_of(issue_time, required_horizon_minutes)` selects one cycle for the entire forecast. Default assumed bundle availability is cycle + **6 hours**, and eligibility requires availability ≤ issue time. Required leads are retrieved from f001 through the end of the requested horizon so accumulation history is available. Later valid times are expected for a forecast; later initialization/availability times are forbidden. A known-bundle-availability mapping is supported by the selector; unknown cycles are ineligible in that mode.

Six hours is an explicit conservative **assumption**, not measured historical publication time. Every affected output is flagged `ASSUMED_AVAILABILITY`. Archive existence today does not establish its original release time. Thus replay readiness is conditional on this documented latency policy, not proof against an exceptional historical publication delay. No GPM observations, test targets, training, or fitted weights enter GFS selection or processing.

## Storage and reproducibility

Separate immutable store: `data/processed/gfs_replay/gfs_mumbai_locked_test_replay_v1/`. Each event/issue directory contains compressed `rainfall.npz` and `metadata.json`; the top-level completion manifest is published only after all 51 samples. Stored arrays include output rate, hourly reconstructed rates on the target grid, native interval boundaries, output valid times and leads. Metadata holds cycle, assumed availability, age, source product/interval/URI/hash, conversion, grid and QC details. Existing issue files can be reused only after recomputation, matching provenance/hash and array checks; no overwrite is permitted. Published versions cannot be regenerated in place.

Commands (from repository root):

```powershell

python scripts/verify_gfs_replay.py data/processed/gfs_replay/gfs_mumbai_locked_test_replay_v1
```
